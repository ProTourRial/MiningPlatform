# Upgrade v0.3.0-alpha.2 to v0.3.0-alpha.3

## Scope

The schema moves from version 8 to 9 through migration `20260813010000_versioned_fee_policy`.

## Before upgrade

1. Stop writers that create accounts or reward allocations.
2. Take a verified database backup and record the installed release manifest.
3. Confirm all alpha.2 migrations are applied and the database copy used for rehearsal is disposable.
4. Review custom `MiningAccount.platformFeePercent` values; exact 2.0000 values are treated as the former alpha default.

## Migration behavior

- Creates retired legacy default v0 at 2% for historical traceability.
- Creates active default v1 at 0.5% (50 basis points).
- Moves accounts still on the exact former 2% default to v1 and 0.5%.
- Preserves every non-2% custom account fee as a scoped account policy.
- Preserves all historical reward-allocation monetary values and attaches a legacy rate snapshot.
- Adds database checks for policy windows, scopes, basis points, account fee bounds, and allocation amount equality.

## Rehearsal

Run only against an explicitly disposable database copy:

```bash
MIGRATION_TEST_ACK=v030-alpha2-upgrade-copy pnpm verify:migration:v030-alpha3:upgrade
```

For a fresh empty database:

```bash
MIGRATION_TEST_ACK=v030-alpha3-fresh-empty-database pnpm verify:migration:v030-alpha3:fresh
```

Both commands require `DATABASE_URL` and `psql`. A local disposable PostgreSQL Docker container can be used instead by setting `MIGRATION_PSQL_CONTAINER` to its container name; CI continues to use the host `psql` client.

## After upgrade

1. Confirm `platform-default` v1 is active at 50 basis points.
2. Confirm every mining account has a valid `feePolicyId`.
3. Confirm historical allocations retain gross, fee, and net amounts and have `legacyImported=true` snapshots.
4. Run API integration, type, unit, build, static release, and manifest gates.
5. Resume writers only after monitoring and rollback ownership are confirmed.

## Rollback

This migration intentionally does not provide destructive down SQL. Restore the pre-upgrade database backup and the alpha.2 application artifact together. Do not run alpha.2 binaries against schema version 9.
