## Local commit gate

All local gates above passed before commit. Root lint, typecheck, and tests are repeated after final documentation and manifest generation; the production build already passed after the final product and migration changes.

The upgrade rehearsal first deploys the complete v9 migration chain, runs the normal alpha.4 seed,
inserts representative prior-schema user, mining-account, pool, reward-period, allocation, and
reconciliation rows with non-zero provider costs, and only then applies v10 and verifies the
backfill and database guards. This is real prior-version relational data in a disposable database,
not a claim that a production snapshot exists; a sanitized production snapshot remains required
when such an environment becomes available.

Repository CI on the pushed commit remains an additional independent gate. It cannot authorize production providers, custody, or real funds.
