# MiningPlatform v0.3.0-alpha.2 — Control Plane Hardening

Release date: 2026-08-03

This release hardens the v0.3.0-alpha.1 control plane. Wallet signing, user deposit crediting, reward settlement, and payout execution remain disabled.

## Implemented

- Root-level GitHub Actions definitions for quality/build, fresh migration, upgrade migration, release packaging, and Docker Compose smoke testing.
- Frozen-lockfile installation in CI and all application Dockerfiles.
- PostgreSQL and Redis service containers in CI.
- PostgreSQL-backed authentication integration coverage, including parallel refresh requests.
- Atomic refresh-token rotation with persistent token-family history and family-wide revocation on replay.
- Transactional logout/password-reset revocation of refresh-token records.
- Transactional worker deletion and credential revocation.
- Duplicate worker-name conflict detection and Prisma `P2002` mapping to HTTP 409.
- Bounded authentication access-token and refresh-token TTL configuration.
- API-key request authentication through `x-api-key` with scope enforcement (already present in alpha.1 and retained).
- Transactional identity-email delivery adapter using the PostgreSQL outbox and Resend.
- Refresh-token replay Prometheus metric and alert rule.
- Database snapshot/restore tooling and migration rollback procedure.
- Disabled-by-default public receiving-address registry for maintenance donations and future site payments.

## Receiving-address safety boundary

The configured addresses are public receiving addresses only. No private key, seed phrase, signer, automated deposit recognition, user balance credit, or payout path is introduced. The endpoint `/api/v1/wallets/support-addresses` returns addresses only when `SUPPORT_PAYMENTS_ENABLED=true`; the default is `false`.

The user-provided Tron label `TRC2` is normalized to the established token-network label `TRC20` in code.
