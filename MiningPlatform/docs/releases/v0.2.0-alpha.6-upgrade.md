# Upgrade alpha.5 to alpha.6

Owner: Abia Nugrahanto

## Before applying

1. Back up the alpha.5 source tree.
2. Back up PostgreSQL using a tested restore procedure.
3. Record the current `/version` response and Git commit.
4. Stop Stratum ingress before migrating a shared environment.

## Apply patch

Extract the incremental archive over the alpha.5 project and run:

```bash
bash apply-patch.sh
```

PowerShell:

```powershell
.\apply-patch.ps1
```

No alpha.5 files require deletion in this release.

## Verify dependencies and generated client

```bash
corepack enable
corepack prepare pnpm@10.13.1 --activate
pnpm install --frozen-lockfile
pnpm db:generate
pnpm typecheck
pnpm test
pnpm build
```

Or run:

```bash
pnpm verify:alpha6
```

## Migration validation

Fresh disposable database:

```bash
MIGRATION_TEST_ACK=alpha6-fresh-empty-database \
DATABASE_URL='postgresql://...' \
pnpm verify:migration:alpha6:fresh
```

Disposable copy upgraded from alpha.5:

```bash
MIGRATION_TEST_ACK=alpha5-upgrade-copy \
DATABASE_URL='postgresql://...' \
pnpm verify:migration:alpha6:upgrade
```

Never run migration verification against the only production database.

## Runtime configuration

Use `UPSTREAM_DRIVER=multi` and provide `UPSTREAM_POOLS_JSON`. Keep VarDiff disabled until provider fixtures and a long-running statistical test have passed.

## Rollback

Application rollback requires restoring the alpha.5 source and database backup. PostgreSQL enum additions and schema changes are not automatically reversible by the patch script.
