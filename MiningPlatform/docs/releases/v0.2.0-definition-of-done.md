## Functional Acceptance Criteria

### Stratum

- Parses newline-delimited Stratum V1 JSON-RPC safely.
- Supports `mining.configure`, `mining.subscribe`, `mining.authorize`, and `mining.submit` for the supported upstream profile.
- Relays upstream `mining.set_difficulty`, `mining.set_extranonce`, and `mining.notify` messages.
- Enforces message size, connection, authentication, and submission rate limits.
- Disconnects malformed or abusive sessions through a documented policy.

### Share validation

- Reconstructs the submitted header for the assigned job.
- Calculates double SHA-256.
- Compares the result with the assigned share target.
- Detects duplicate, stale, malformed, unauthorized, and low-difficulty submissions.
- Persists the local result before downstream projection.
- Records the upstream result separately from the local result.

### Event bus and idempotency

- Publishes events through a transactional outbox where a database fact and event must remain atomic.
- Handles duplicate event delivery without duplicate database effects.
- Moves exhausted messages to a dead-letter stream.
- Propagates correlation IDs across Stratum, worker, API, and WebSocket logs.

### Monitoring

- Displays worker online, degraded, and offline states.
- Displays accepted, rejected, stale, and invalid share counters.
- Displays hashrate for 1-minute, 5-minute, 15-minute, 1-hour, and 24-hour windows.
- Updates the dashboard through WebSocket without requiring a page refresh.
- Persists bounded time-series snapshots and applies retention jobs.

### Testing

- Unit tests cover target calculation, difficulty calculation, state transitions, duplicate keys, stale rules, and hashrate windows.
- Integration tests cover PostgreSQL, Redis, outbox dispatch, and consumer idempotency.
- Protocol tests cover valid, malformed, repeated, unauthorized, low-difficulty, and stale submissions.
- An end-to-end test miner completes the required pipeline.
- Load testing records connection count, submissions per second, p95 validation latency, event lag, and WebSocket update delay.

### Operations

- Health endpoints cover PostgreSQL, Redis, upstream connection, event lag, and WebSocket gateway.
- All scheduled work is dispatched from the scheduler deployment.
- Structured logs exclude miner passwords and sensitive credentials.
- Metrics and alerts exist for rejected share spikes, upstream disconnects, consumer lag, dead letters, and database errors.

## Explicitly Excluded

- Final reward settlement.
- Journal posting of user rewards.
- Production Bitcoin wallet RPC.
- UTXO selection and PSBT signing.
- Real payout broadcast.
- Native block-template generation.
- Coinbase transaction construction.
- Independent block propagation.
- Production claims for pool luck or blocks found.

## Release Gate

The release is not complete when only controllers, interfaces, database models, or dashboard placeholders exist. The end-to-end pipeline must run with deterministic automated tests and a repeatable local environment.
