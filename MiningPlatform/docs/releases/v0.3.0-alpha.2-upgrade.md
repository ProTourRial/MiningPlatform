# Upgrade v0.3.0-alpha.1 to v0.3.0-alpha.2

## Repository layout

Extract the supplied archive at the root of `ProTourRial/MiningPlatform`. The archive contains:

```text
.github/
MiningPlatform/
```

The root `.github/workflows` directory is intentional. GitHub does not discover workflow files stored under `MiningPlatform/.github/workflows`.

## Required configuration

Keep these features disabled until their external dependencies are provisioned:

```env
EMAIL_PROVIDER=disabled
RESEND_API_KEY=
EMAIL_FROM=MiningPlatform <no-reply@example.test>
SUPPORT_PAYMENTS_ENABLED=false
```

When email is ready, set `EMAIL_PROVIDER=resend`, provide a valid API key and verified sender, and keep `APP_URL` on HTTPS in production.

## Database upgrade

1. Create and test a PostgreSQL snapshot as described in `docs/operations/database-backup-and-rollback.md`.
2. Run the upgrade verification against a disposable database copy:

```bash
MIGRATION_TEST_ACK=v030-alpha1-upgrade-copy \
DATABASE_URL='postgresql://...' \
pnpm verify:migration:v030-alpha2:upgrade
```

3. Deploy the application only after CI is green.
4. Apply the migration in the target environment:

```bash
pnpm db:migrate:deploy
```

The new migration is `20260803040000_auth_session_rotation_hardening`. It adds `AuthSession.tokenFamilyId`, creates `AuthRefreshToken`, and backfills each existing session's current refresh-token hash.

## Required acceptance checks

- `CI / quality`
- `CI / migration-fresh`
- `CI / migration-upgrade`
- Docker E2E workflow for changes touching Compose, Dockerfiles, applications, or packages
- login, refresh rotation, logout, password reset, Worker CRUD, API-key scope, and Stratum authorization smoke tests

Do not enable wallet signing, payout execution, or automatic user balance crediting in this release.
