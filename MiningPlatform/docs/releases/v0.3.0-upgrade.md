# Upgrade v0.2.0-alpha.6 → v0.3.0

Author: Abia Nugrahanto

## Before upgrade

1. Back up the repository and database.
2. Confirm the source version is `0.2.0-alpha.6`.
3. Do not apply the migration to the only production database copy.
4. Configure strong `AUTH_JWT_SECRET`, `AUTH_ENCRYPTION_KEY`, `AUTH_BACKUP_CODE_PEPPER`, and `SENSITIVE_VALUE_HMAC_KEY` values.

## Apply files

Extract the incremental patch over the repository and run:

```bash
bash apply-patch.sh
```

Windows:

```powershell
.\apply-patch.ps1
```

## Dependency and client verification

```bash
corepack enable
corepack prepare pnpm@10.13.1 --activate
pnpm install --frozen-lockfile
pnpm db:generate
pnpm typecheck
pnpm test
pnpm build
```

## Database verification

Fresh disposable database:

```bash
MIGRATION_TEST_ACK=v030-fresh-empty-database pnpm verify:migration:v030:fresh
```

Disposable copy of an alpha.6 database:

```bash
MIGRATION_TEST_ACK=alpha6-upgrade-copy pnpm verify:migration:v030:upgrade
```

Check that existing users receive USER or OWNER role assignments and that no duplicate user relation fields exist in the Prisma schema.

## Operational checks

- `GET /version` reports `0.3.0`, schema `7`, and migration `20260731190000_identity_access`.
- Registration creates a pending account.
- Verification activates the account.
- Login creates a visible session.
- Session revoke invalidates the JWT despite its signature remaining valid.
- Worker CRUD and credential rotation are ownership-scoped.
- Production rejects development delivery mode and memory-only authentication rate limiting.
