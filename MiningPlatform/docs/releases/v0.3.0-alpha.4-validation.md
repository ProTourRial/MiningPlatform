## Defects discovered and closed during validation

- Turbo did not originally forward `REDIS_INTEGRATION_URL`, causing the root suite to skip cross-client Redis coverage. The variable is now part of the test task environment and the root run proves 13/13 Stratum tests with no skip.
- The failover regression used a 500 ms test-only connection budget and could select backup under parallel CI pressure. The test now uses a realistic budget, asserts primary selection before induced failure, passes five consecutive package runs, and passes the root suite.
- Five service Dockerfiles omitted the author-header helper required by `db:generate`. Clean Stratum and API container builds now pass.
- Docker E2E called nonexistent `/api/v1/version`; it now verifies the canonical version-neutral `/version` route.

## Redis integration assertions

1. Separate coordinator clients observe one shared provider circuit.
2. An open primary is skipped by another manager instance in favor of its backup.
3. Exactly one coordinator receives a half-open probe lease after recovery timeout.
4. A successful probe clears consecutive failures and re-enables ordinary connection attempts.
5. Redis server time controls lease and circuit expiry.
6. Coordinator failure remains fail-open to the local circuit breaker and emits an error signal.
7. Health snapshots and Redis keys never store provider usernames or passwords.
