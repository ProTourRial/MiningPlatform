# MiningPlatform v0.3.0-alpha.7

Status: payout-control foundation alpha
Schema: 13
Migration: `20260822010000_payout_control_foundation`
Upgrade source: `0.3.0-alpha.6`

## Purpose

Alpha.7 closes the first two foundation steps of controlled funds: an explicit Asset/Network/PayoutRoute catalog and replay-resistant payout-address management. It deliberately does not create, sign, broadcast, or confirm a payout.

## Added

- Versioned immutable `AssetNetwork` and `PayoutRoute` records with effective windows, registration/pilot/active status, threshold, network fee, cooldown, confirmation, and manual-approval policy.
- Password+TOTP payout step-up authorization bound to the interactive session and scope, stored only as a hash, valid for five minutes, consumed once, and protected by one TOTP replay counter shared with enrollment, login, and factor disablement.
- Offline Bitcoin mainnet address validation for Base58Check and BIP-173/BIP-350 Bech32/Bech32m.
- Address registration, activation after cooldown, one-active-address-per-route replacement, one-way disablement, audit events, masked API reads, and dashboard controls.
- Database triggers for step-up immutability, route version immutability, address lifecycle/identity integrity, and payout-to-route/address alignment.
- Explicit payout-read API-key scopes, interactive-only preference mutation, enabled-factor re-enrollment rejection, and browser refresh single-flight coverage.
- Fresh and alpha.6 upgrade migration verifier with representative legacy address and payout data.

## Safety boundary

- Checksum validation proves address syntax and network, not ownership of a private key.
- The seeded BTC route is `ADDRESS_REGISTRATION`; it can accept address enrollment but the database rejects payout creation through it.
- `PILOT` routes may only create payouts in `REVIEW` and cannot leave review through a status-only update until a future approval control exists; inactive routes may only transition to safe terminal cancellation/failure.
- Complete payout addresses are not returned by normal read APIs.
- Auto withdrawal remains a stored preference, default `OFF`, and remains ineffective.
- `PAYOUTS_ENABLED=false` remains mandatory. Wallet signing, balance reservation, payout execution, broadcast, confirmation, reorg handling, and real funds remain disabled.

## Compatibility

The migration backfills legacy payout addresses onto the BTC mainnet route, derives network-bound SHA-256 address fingerprints, retains existing activation state, and binds existing payout rows to the new route. Fresh and alpha.6-upgrade rehearsal are mandatory before promotion.

## Remaining blockers

- Payout eligibility and immutable balance reservation.
- Idempotent payout simulation and state machine.
- Isolated signer, approval separation of duties, wallet/node health, and emergency stop.
- Broadcast, confirmation, reorg, fee bump/retry, and wallet/blockchain reconciliation.
- Controlled-funds pilot, risk/compliance approval, operational drills, and independent security review.
- Provider fixtures, load/soak/chaos evidence, production infrastructure, and external operational ownership.
