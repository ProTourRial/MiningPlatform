# Validation Report v0.2.0-alpha.3

Release name: **Local Upstream Gateway Pipeline**

Validation date: 2026-07-31

## Scope

This validation covers the local protocol and domain pipeline that can run without Docker:

```text
Downstream test miner
    ↓
MiningPlatform Stratum gateway
    ↓
Local SHA-256d validation
    ↓
Upstream Stratum simulator
    ↓
Response correlation
    ↓
UPSTREAM_ACCEPTED / UPSTREAM_REJECTED lifecycle
```

It does not certify compatibility with a selected production pool, PostgreSQL/Redis runtime integration, Docker images, production ASIC traffic, reward settlement, wallet operations, or real funds.

## Protocol coverage

The automated suite verifies:

- downstream `mining.configure`, `mining.subscribe`, `mining.authorize`, and `mining.submit`;
- upstream subscribe and authorize request-response correlation;
- `mining.set_difficulty`, `mining.set_extranonce`, and `mining.notify` parsing and relay;
- normalized job registration;
- `clean_jobs` invalidation;
- local SHA-256d target validation;
- upstream accepted and rejected responses;
- initial connection retry with deterministic exponential backoff;
- full TCP flow from a downstream test miner to the local upstream simulator;
- the rule that the downstream success response is sent only after upstream acceptance.

## Bitcoin compatibility fixture

The reference fixture validates:

- coinbase composition;
- internal coinbase double-SHA-256;
- Merkle processing;
- the complete serialized 80-byte header;
- the displayed double-SHA-256 header hash.

The fixture is a public Stratum V1 reference example. It is not a captured fixture from the production upstream provider that will eventually be selected. Provider-specific fixture tests remain a staging blocker.

## Typecheck boundary

The Stratum application passed an isolated TypeScript typecheck. The mining worker also passed its isolated typecheck while using a temporary local database module stub because the environment could not install the Prisma-generated workspace dependency from the package registry. A full clean-workspace typecheck must be repeated after the first networked `pnpm install` and `pnpm db:generate`.

## Environment limitations

The validation environment did not provide:

- npm registry access for generating `pnpm-lock.yaml`;
- Docker daemon access;
- running PostgreSQL and Redis services;
- a selected public upstream account and captured provider fixture.

Therefore the following remain unverified:

- frozen-lockfile clean installation;
- full Turborepo dependency-aware build;
- PostgreSQL transactional outbox integration;
- Redis duplicate reservation and pending recovery against a real Redis instance;
- Docker Compose health and networking;
- TLS behavior against the selected upstream provider;
- multi-replica and load behavior.

## Release decision

```text
Local protocol development: PASS
Internal alpha demonstration: PASS
Selected upstream staging: NOT READY
Production ASIC traffic: NOT ALLOWED
Reward settlement: NOT ALLOWED
Wallet or real funds: NOT ALLOWED
```

The repository is suitable as the next local-development baseline. The next gate is provider-specific compatibility plus durable PostgreSQL/Redis integration once the Docker environment is available.
