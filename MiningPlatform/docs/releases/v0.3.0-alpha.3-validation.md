## Upgrade assertions

The disposable alpha.2 dataset proved that:

1. an account on the former exact 2.0000% alpha default migrates to `platform-default` version 1 at 50 basis points and stores 0.5000%;
2. a custom account at 1.2500% remains 1.2500% and receives a scoped account policy at 125 basis points;
3. a historical reward allocation at 2% retains gross 1.00000000, fee 0.02000000, and net 0.98000000;
4. that allocation receives policy version 0, 200 basis points, and `legacyImported=true` in its immutable snapshot.

## API and public disclosure assertions

- New-account registration stores a relation to `platform-default` version 1 at 50 basis points and exposes 0.5 as the account percentage.
- Public system configuration resolves the database policy instead of a source-code fee constant.
- The landing page discloses `Platform fee awal` as `0,5%`.
- Invalid, future, inactive, and ambiguous fee-policy cases are covered by deterministic tests.

## Environment-specific build note

Windows local builds omit Next.js standalone tracing because creating pnpm symlinks requires a platform privilege not available in this workspace. Linux CI and the web Dockerfile set `NEXT_OUTPUT_MODE=standalone`, so the deployable standalone artifact remains mandatory in those environments. The application source, route generation, and all non-standalone production build steps passed locally.

This validation closes P0.1 only. It does not validate real upstream providers, production load, durable settlement posting, reconciliation, wallet signing, conversion, payouts, custody, or legal/compliance readiness. Real funds remain prohibited.
