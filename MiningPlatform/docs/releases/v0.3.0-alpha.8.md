# MiningPlatform v0.3.0-alpha.8 Candidate

**Schema:** 23
**Latest migration:** `20260908010000_google_oauth_identity_foundation`
**Status:** Feature-branch candidate; not authorized for real funds or public mining traffic

This candidate consolidates the controlled payout regtest path, RandomX loopback laboratory,
professional frontend, authenticated browser journey, and optional Google federated sign-in on top of
the alpha.7 control-plane and financial-truth foundation.

## Identity contract

Google Sign-In is disabled by default. When configured, it authenticates only a Google provider
subject explicitly linked to an existing active MiningPlatform account. Linking and unlinking require
the account password, TOTP, a session-bound single-use step-up token, matching verified email, PKCE,
state, nonce, and a short-lived browser-bound callback proof. Email matching alone is never identity
proof. Google tokens are not stored and are not reused as MiningPlatform session credentials.

## Release boundary

- Bitcoin payout execution remains regtest-only and all real-funds gates remain disabled.
- RandomX runtime remains restricted to an acknowledged loopback laboratory and cannot start in
  production mode.
- Native Bitcoin job/candidate/submission evidence is not a production Stratum pool.
- Google OAuth remains invisible until the backend has a complete provider configuration and a stable,
  exact HTTPS callback domain.
- Production promotion still requires exact-commit CI, Docker/browser smoke, external security review,
  custody authorization, HA/DR evidence, and operator sign-off.
